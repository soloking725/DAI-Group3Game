🧬 Difficulty Bot

Evolves a small neural net to play the real game (real player.js/enemy.js/ boss.js, not a mock) against a chosen roster in the bounded bot_arena room. Evaluation runs fast-forward (no rendering); after each generation the current best genome is replayed live at real speed so you can actually watch it fight — see the plan doc for the full design.

1. Roster

Spawn positions are spread evenly across the arena — no manual placement needed.

2. Player Loadout

Lore Pips Used0 / 30

Level 0-4 = the real lore-pip-funded tiers, costing 1/2/3/4 pips each (cumulative — Lv4 costs 1+2+3+4=10 total; 2026-07-27 rebalance added a cheap Lv1 "small boost" and shifted the old Lv1-3 up to Lv2-4), same table game.js's Inventory screen uses. Level 5 = Limit Break — a permanent Enhanced State for that one ability, no pip cost (bypasses the real per-playthrough limit for testing, same as enemy_test.html) — doesn't add to the pip count below. Only one ability may be Lv5 at a time — that's the actual in-game rule, not a bot limitation. 30 is the current target lore-pip total for a full playthrough (deliberately short of maxing every line — specialization is the point) — going over it is still runnable here, just not a loadout a real playthrough could ever reach at once.

3. Search Algorithm

Baseline ignores the settings below — it's one run of a fixed policy, not a search. GA and ES both evolve the same net; the difference is only in how children are produced each generation.

4. Evolution Settings

1 = re-decide every simulated tick (very twitchy, snaps direction instantly — this was the "turns around really quickly" issue). Higher = holds each decision longer before reconsidering, closer to real reaction time (6 ≈ 100ms @60fps) — also lets hold-to-charge actions (attack, Shard Shot, Graviton Surge) actually commit instead of flickering on/off.

Fast-forward evaluation is one long synchronous burst of game-logic calls per genome with nothing to make it yield — that's almost certainly the fan/heat. This inserts a real pause between genomes so the CPU actually gets a break; higher = cooler but slower to finish.

How many generations is "enough"? There's no fixed number — watch the chart below: keep going while best fitness is still climbing, stop once it's been flat for ~15-20 generations in a row (that's a plateau, not a countdown). Rough starting points: a single Fractured usually shows real learning within 20-40 generations; 2-3 enemies or a miniboss often needs 60-150+; the King can need more. If it can't reliably clear 2 Fractured yet, that's expected before ~50+ generations — the 3-target awareness window (was 2) and the reaction-time throttle above both help, but multi-enemy fights are a harder problem than 1v1 and need more generations to solve, not a sign something's broken. Start small (1 enemy), confirm it's actually learning, then scale up roster size — jumping straight to the full roster or the boss makes it much harder to tell "still training" from "stuck."
